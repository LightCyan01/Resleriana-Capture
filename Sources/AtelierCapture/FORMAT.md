# Capture archive format

Each schema-4 or schema-5 capture is one ZIP for one run ID and environment, with exactly five flat entries: `api.jsonl`, `combat.jsonl`, `raw-bodies.jsonl`, `diagnostics.jsonl`, and `manifest.json`. JSONL streams are strict UTF-8 JSON objects terminated by LF; API/combat/raw streams may be empty. The format is `resleriana-capture`, manifest version 1. Recording uses complete gzip members at Fastest; packaging uses ZIP Optimal and the platform ZIP64 implementation.

ZIP names retain the previous `capture-YYYY-MM-DD_HH-mm-ss.zip` format. A numeric suffix such as `-2` resolves occupied names without replacing an existing recording. Run IDs remain inside the manifest and records.

Each plaintext `entries` row has `name`, `sha256`, `bytes`, and `records`. Hash exact extracted bytes including line endings. `records` counts LF bytes and must equal validated object count. Metadata, producer/client/runtime identity, session/recovery status, coverage and all counts are readable. The recorder does not assign eligibility or points; the user manually reviews captures. There are no count-protection fields or keys.

## Optional privacy policy in 1.4.1

Default capture remains full raw. `BepInEx/config/AtelierCapture.Privacy.json` contains one boolean `enabled`, default `false`, frozen before any writer or diagnostic subscription starts. Invalid explicit configuration stops recording. With privacy enabled, schema 5 and count-summary version 2 remain in use, with the same five entries.

`metadata.privacy` declares `enabled`, `policy_version: 1`, `mode` (`full_raw` or `filtered_gameplay`), `account_import_complete: false`, `original_bodies` and `uncertain_evidence`. Filtered session starts and manifests set `contains_sensitive_raw_data: false`; this describes the omitted originals and does not certify anonymity or authenticity. Legacy metadata without a policy continues to describe the original full capture.

The filtered writer preserves qualified API gameplay numbers, booleans, finite enum values, typed timestamps and nested known protocol fields. It retains catalog and owned-entity linkage and ordered collections, while excluding credentials, account/device identifiers, profiles, birth fields, arbitrary text, bytes and unknown fields/types. String-typed numeric descriptions are omitted unless their protocol type itself is numeric. `Privacy/PrivacyFields.json` pins the permitted field contract to the JP 2.16.0 descriptors. A projected API body has `source: privacy_gameplay_projection` and `omitted: privacy_mode`, even when some qualified payload remains; its payload is not the original complete response.

Original and derived raw observations retain only local ownership, route, direction/stage and `omitted: privacy_mode`. They have no `body`, `bytes`, `sha256` or digest-bearing `body_id`; those forbidden fields invalidate a privacy omission even when null. Raw-stage record counts therefore include omission facts, not retained original bodies. Personal native operation/header/descriptor identifiers and their proof claims are removed. Recorder-local request, attempt, response and native invocation identities remain for pairing.

Native records retain qualified boundary/variant/system and invocation identity, with `complete: false` and omitted values. They do not provide the native snapshots available in full mode. Arbitrary diagnostic logs, startup file prefixes, parsing bytes, failures and exception text become finite `privacy_omission` records. Entire warning/error aggregation families are omitted together rather than leaving orphan anchors or repeats. Generated producer status is a privacy gap, and explicit abort reasons use a fixed code. Physical saved counts, integrity validation and incomplete reasons still apply.

Filtering happens before compressed records and checkpoints are written. Recovery in enabled mode only packages runs declaring the supported filtered policy; earlier full or unknown-policy originals remain unchanged and pending. Recovery never changes a saved run's declaration to match the current setting. Existing archives and separate BepInEx/Unity log files are not sanitized. Retained progress can identify a player and lacks data needed for a complete account import. The [account and session disclosure](https://github.com/LightCyan01/Resleriana-Capture/blob/main/docs/account-and-session-data.md) explains the user-facing limits.

## Reading gameplay evidence for server implementation

The capture contract applies to every observed skill, effect, recipe and operation. There is no effect-ID, recipe-ID or current-server-support filter. Start with the manifest's client/producer identities and coverage gaps; then read `api.jsonl` in saved sequence order. The observed login/version payload supplies `master_data_version` and `asset_version` where present; join those to the matching master data rather than assuming the manifest embeds a complete master catalog. Match requests/responses with their recorded request, attempt, operation and response identities. A callback, repeated response body or repeated history is not an independent gameplay trial. Never join by whichever request happened most recently.

Resolve native node references only inside their observation using its node IDs and `snapshot_contracts`. Preserve collection and action order, explicit null versus empty, exact wide integers and floating-point representations. Native lifetime identity is a correlation fact, not permission to reuse mutable values from another observation. `receiver_state_not_observed` deliberately records the receiver identity without claiming its internal storage was read.

For the pinned JP2.16.0 client, observed constructor/consumer contracts identify these native domain models: `CGGKFDGOFGN` corresponds to BattleHistory, `JCDJDPMCAPB` to BattleAction, `HMIEBOKCGFE` to BattleActionSetup, `LACKKEMGIJD` to BattleState, `DACMCGLDEEH` to BattleMember, `JKHFJKGHLHF` to BattleEffectResult, `FGGLBOCKLIJ` to BattleHitResult and `ONLJOBBGNHI` to BattleStateChange. Use the actual protobuf schema and constructor/consumer input to interpret their raw stored fields; an obfuscated field name alone does not establish a semantic alias. `NAKLKNNBDMC` retains Atelier selection data and `OLJAEFPIMBE` maps the synthesis response/result. Client-version differences require requalification of these mappings.

Saved-byte integrity, observed gameplay and a recovered rule are different conclusions. A complete paired API exchange can give an implementation regression vector even when an unrelated native UI field is unavailable. Conversely, a valid ZIP or successful native call does not establish an unseen expiry/stack/trigger rule, application probability, hidden synthesis weight or backend RNG state. Evaluate the relevant command, ordered transitions and required values; retain exact missing fields or unplayed variants as gaps. Do not treat `task_return` as asynchronous completion or a historical repeated action as a second sample.

## General native gameplay scope

Native projections preserve declared gameplay data for every observed ID, including unfamiliar effects. Complete actual arguments/results and full mapped domain messages remain; selected controller snapshots retain fresh current state, setup, units, counters and numeric values. Explicit history/controller lifetime references identify an object without recopying its entire reachable history or rendering graph. They do not promise that omitted mutable state can be recovered from another record. Unclassified stored gameplay fields retain their normal read or explicit qualification failure; there is no default-drop filter by class name, skill ID, collection size or graph depth.

For the pinned Battle contract, the three stored current BattleState models, current ActionSetup, scalar/nullable values, gauges/cursors, ordered domain collections, unit stats/resistances and condition data remain fresh. The explicitly identified history/action/setup collection edges use typed lifetime references. Exact actor scene-vector/renderer/movement/presentation links are outside this server-evidence scope; logical formation positions, domain timeline/panels and complete action/effect results remain gameplay data. The selected-domain contract does not claim the entire native mutator state or transitive mutation closure was observed. Historical fuller controller snapshots remain readable under their original declared contracts.

`general_gameplay_domain_v3` adds exact field-scoped references for the qualified timeline scheduler continuation, support-ability view and command-item view links. The expected concrete native class must match the pinned declaration, module and registered class identity. Other implementations retain their normal full read or explicit failure. Command-item collections keep their ordering, duplicates and nulls; only the qualified view elements use lifetime references. `scheduler_callback_state_not_observed` and `presentation_view_state_not_observed` explicitly exclude those internals from state observations. A reference at one field does not replace the same object's full arguments/results or any Battle/Atelier domain values. Previous recordings retain their original projection contracts.

## Durable prefixes and retained originals

Schema-5 recording uses `session-state.0.json` and `session-state.1.json`, checkpoint schema 2. The shared StorageCheckpoint serializer defines the ordered checksum payload: schema, generation, run_id, environment, streams (ordered name/bytes/sha256/records/extracted_bytes), committed_batches. `checksum` is SHA-256 over exact canonical shared payload bytes excluding the checksum field. All touched complete gzip members and the selected checkpoint pass durable flush before callback acknowledgement. Observations already queued commit together under one flush and one generation; `committed_batches` still counts each observation.

Current `metadata.durability` describes each observation class explicitly. Gameplay/network and ordinary diagnostics are durable before callback continuation. Outer warning and known material-error callbacks return after queue admission; normal shutdown drains admitted diagnostic occurrences before writing summaries, but abrupt termination can lose occurrences still queued. Nested diagnostics share their outer observation's save boundary. Older producers used a single string declaration; retain that original metadata when reading existing captures rather than assuming the newer queued exception from its schema alone.

The archive checks both slots, rejects conflicting run/environment or same-generation vectors, selects the newest valid metadata, then verifies its exact compressed prefix bytes/hash, gzip CRC/framing, extracted bytes and records. A corrupt slot can fall back to its valid peer; a valid metadata vector with invalid source data is a failure rather than silently choosing a shorter recording. Schema-4 `session-state.json` schema 1 remains supported with exact prefix binding. Missing/invalid commit metadata never permits guessed packaging. Unknown/process bootstrap state produces no fabricated third ZIP.

Native observation payloads use `snapshot_schema: 2` with a self-contained `snapshot_contracts` table. Each flat node's `contract_id` selects that record's exact contract `id`, `type`, `excluded_fields` and `unavailable_fields`. Reconstruct the prior logical node by attaching those three declarations to the node; no earlier record, native object or external catalog is needed. Separate contracts preserve differing declarations even when their type names match. Node IDs, field values and nulls, item order, lifetime identities, protobuf bytes/hashes, representation, dynamic failures and lineage facts remain in the observation. Required-field completeness still checks unavailable declarations. Historical payloads with inline node declarations remain valid. This local snapshot version does not change outer schema5, the five ZIP entries or physical record/native-call counting.

The node annotations `items`, `protobuf`, `protobuf_sha256`, `representation`, `lifetime_id` and `lineage_failures` are optional when their value is null. Missing means logical null; readers may restore null to reconstruct the older explicit-null node shape. Empty arrays, empty protobuf bytes and empty lineage lists remain present and distinct. Explicit null gameplay field values and null collection elements always remain in their dictionaries/arrays. This applies only to these six node annotations, with no global null filtering or change to original API data.

Only the verified `BattleStateVariables.GetClientBattleStatus` boundary at RVA `0x4192D30` uses `native_client_status_read_set_0x4192d30_v1`. Its receiver preserves the three source-object lifetime references, the stored `_size` of both action lists, the stored flag and mapped-history status read by that native method. Null source objects and unavailable reads remain explicit. The receiver contract declares fields outside that qualified read set; it does not claim a full owner snapshot. Actual arguments, return values and all other hook receivers retain their normal gameplay projection. Projected and full views have distinct local identities, so observing the same owner as an argument still copies its full supported gameplay fields.

Compiled native reader/declaration metadata may be reused by exact CLR type under the verified client; every mutable native field is read afresh. Exact CLR value readers preserve stored Vector3/Quaternion float component bits and DateTime `_dateData`, including flags; equal boxed value structs do not share a native identity. Qualified timeline actor membership uses ordered lifetime references while its local stored timeline data is copied. Unknown origins remain explicit diagnostics. Successful native parse observations bind the concrete root and its actual stored protobuf children before mapped consumers, keeping origin proof separate from operation ownership; delayed conflicts invalidate affected descendant operations without borrowing the latest request. Read failures remain complete failure evidence and prevent a successful lineage-completeness claim.

Qualified `_ee847`/`_67f24` value structs preserve their original nested `m_value`, `e`, `s` and `c` storage without invoking decoding properties. Protobuf child binding follows stored object/interface oneof payloads using the actual native type, treats qualified scalar boxes and enums as nonedges, and retains unknown types or failed reads as gaps. Original protobuf/API bytes are unchanged.

Five qualified native interface/abstract views may resolve to their actual concrete wrapper before the normal gameplay projection. The declared view, native assignability, registered concrete class and unchanged pointer must agree under the verified installed interop. Unknown or unsupported concrete classes remain full read failures; an interface name never establishes a complete snapshot. This does not widen Component-owner policy or remove any hook.

The three exact UserDataManager resource consumers use a narrower receiver contract: SetResources@0x2A85190, UpdateResources@0x2A82230 and DeleteResourceEntities@0x2A85070 preserve qualified native owner type/lifetime identity while explicitly leaving receiver state unobserved. All actual arguments retain the normal full snapshot, including complete native-reserialized Resources/ResourceEntities bytes and integrity fields; actual results/faults, phase availability and operation/call identity remain. A receiver reference does not replace a full argument or result even when they share native identity. This records complete admitted resource inputs and observed call outcomes, not the manager's whole account graph or proof that every child cache applied successfully. The full API baseline and original response bodies remain separate evidence. Other boundaries keep their declared receiver contracts.

The `Process` working folder is the durable startup/unattributed spool. Once the first environment resolves, it is frozen and transferred into that environment's diagnostics once; subsequent process-scoped and unbound observations use the selected environment working source with explicit original Unknown provenance. It is not a second ongoing battle mirror. Each admitted observation still durably flushes its touched data and recovery checkpoint before acknowledgement, except deferred warning and known material-error diagnostics, whose callers return once the records are queued. Packaging writes the final ZIP on closure and removes only current working copies proven fully preserved there; unresolved or failed evidence remains retained.

Bytes beyond committed prefixes remain in the original files. The manifest reports retained provisional tail bytes per file and `recovered=true`; nothing is discarded. Recovery appends a `session_recovered` marker to the packaged diagnostics only. Abort sidecar metadata belongs to the same run/environment and is preserved/reported as incomplete. Old, aborted, recovered, provisional-tail and unresolved-only source folders remain retained. CaptureArchive itself deletes no source folder. The current writer may remove only its newly created, normally closed working files after every known environment's final archive passes the exact proof below; the final ZIP remains permanent. Incomplete gameplay coverage does not prevent preservation of every saved byte from being proved.

Packaging creates a new owned candidate, preserves any previous partial candidate, durably flushes the finished ZIP, reopens/recounts/validates it, then moves it to the final path without overwrite. An existing final ZIP is independently verified against its manifest and exact retained source prefixes; it is never replaced. Errors preserve originals and candidates for diagnosis/recovery.

For a fresh normally closed schema-5 candidate, the build verifies each exact compressed source prefix and extracted bytes/records once, retaining four extracted stream hashes/counts and its summary. The independent ZIP read checks full EOF, CRC, strict records, raw bytes/ownership, identities and those source facts. It omits only the redundant second source/ZIP expansion. Existing, legacy and recovered archives keep the full byte-for-byte source comparison. Publication hashes bind the verified candidate to the final file. `PackVerified` returns an in-memory disposable proof holding the final ZIP open with read sharing only, denying writes and deletion throughout writer cleanup; `Pack` remains a compatibility wrapper. The proof binds run/environment, checkpoint hash/generation, four committed source stamps, extracted entries, explicit normal end, tails, abort/recovery and fixed process-bootstrap source ownership/counts. Writer cleanup rechecks current-run ownership and exact source files through stable handles, requires all environments verified, and never deletes old captures or unresolved-only process evidence.

## Readable per-capture counts

New `count_summary` has version 2, scope `single_archive`, basis `verified_packaged_records`, run_id, environment, schema, explicit units and four stream rows. Version 1 remains independently readable with its original semantics, including unbound native diagnostics excluded from native totals; it is not reinterpreted as version 2. Unknown count-contract versions fail. Manifest version 1, schema 4/5 and five entry names remain unchanged. New counters are canonical nonnegative Int64 decimal strings; existing entry bytes/records remain integer JSON tokens. Readers must preserve large integer tokens exactly or reject unsupported values before converting to JavaScript Number.

Stream records partition into envelope_records and marker_records. API request_records and response_records count only request/response kinds; their raw-body copies and transport/completion diagnostics are separate records. Explicit request/attempt IDs produce `observed_send_invocations` and `observed_send_terminal` using their declared identity. `physical_attempts_complete` remains false and physical attempt totals null because HTTP internal sends/retries have not been fully observed. Proven native operation UUIDs give `distinct_observed_operation_ids`; actual operation-start/terminal and hidden internal retry quantities remain null until corresponding boundaries are established. A reported retries scalar does not create captured attempts.

Combat contains both Battle and Atelier with a typed primary system. Unique invocation IDs plus boundary/variant/system identify native entered/returned/thrown/open calls. Entry plus exit is two records of one call. Missing legacy invocation IDs produce null complete-call totals and a separately reported identified subset; never divide combat records by two to invent battles. Async task return is a call return, not actual task/gameplay completion. Gameplay operation totals remain null where unsupported.

Every record has one primary system; cross-system references do not duplicate totals. Fixed supported system rows include Unknown, Service and Recorder. Unknown/new arbitrary labels preserve the record under Unknown without growing an unlimited summary map. Raw bodies are counted by direction/stage and streamed Base64-decoded lengths/hashes are checked. Derived decrypted/decompressed/native protobuf representations do not create extra API requests.

Raw-body ownership is independently joined against saved request records using the bounded sorted ledger. Schema 5 requires known request/attempt IDs to be canonical decimal strings; the pair must identify an actual request, with the same route and primary system. `raw_body_without_request` and `raw_body_request_owner_mismatch` preserve the body and mark observations incomplete. Missing IDs or route produce explicit unverified reasons; they are never guessed from matching bytes/digests/body IDs. Legacy numeric request IDs remain readable; a missing legacy attempt ID permits the request-ID association while reporting `raw_body_attempt_identity_unavailable`. This association does not establish physical retry or logical-operation totals. Multiple materialization stages may reference one request without adding requests.

The shared finite route catalog uses the declared response contract before a family owner: every `BattleStartResponse` route belongs to Battle, including quest/rental/Solo/Total, exploration and gacha battle starts. `/quest/battle/skip` and Solo/Total progression resets stay Quests because they have reward/progression contracts, not Battle start state. Ordinary/rental/preset formation mutators stay Parties even when tools, characters or resource deltas appear. Full `UserLogInResponse`/UserData belongs to Accounts once; resource application is a cross-reference rather than another copy of each request. Auth/account settings stay Accounts; status, advertising-ID and web/KTID token plumbing stay Foundation. Debug routes are diagnostic wire, separate from gameplay domains. A shared `ChangedResourcesResponse` does not reassign every initiating operation to a Resources owner. Network emission and archive recount use this same catalog, so all primary system totals reconcile exactly once to stream totals.

Diagnostic markers lack envelope sequences and do not contribute to session_end.events. Process-bootstrap transfer/reference markers count once as Recorder markers; their original envelope sequences and API records are not recounted as outer events. Version 2 includes actual invocation IDs from the narrowly named unbound_combat/native enter/exit/exception diagnostics, both direct and transferred originals, once in the native census. Their source origin remains Unknown: inclusion in an Official ZIP does not attribute those native observations to Official. Physical stream/system record totals stay partitioned; a process reference in another environment adds no warning/native occurrences. Envelope sequences are unique but need not be consecutive or file-ordered. Historical identity/pairing checks use bounded sorted scratch (4096-row chunks, fan-in 16), not an all-run unbounded HashSet.

Repeated exact warnings retain one full `runtime_log` anchor and one small durable `runtime_warning_repeat` record per later logger callback. Warning and known material-error callbacks queue these records without waiting for their flush; saved totals and final summaries count only flushed occurrences, and a crash can lose occurrences still queued. A repeated warning is hidden from the console when staged. External BepInEx disk logging follows its enabled sources, severity filters and flushing configuration; it is not a guaranteed second durable copy. `runtime_warning_summary` adds no occurrence. Optional readable `warning_summary` reports anchor/repeat/summary records, saved occurrence total, exact first/last UTC and missing final-summary count as canonical Int64 strings. Origin plus warning ID identifies one anchor; repeats must have delta 1 and contiguous cumulative ordinals, with first/last exactly the min/max of saved callback timestamps. Sorting uses ordinal occurrence order, including multi-chunk ledgers and out-of-order timestamps. Duplicated/orphan references, inconsistent ordinals/times or final totals fail packaging with originals retained. A missing final summary reports the saved prefix without inventing loss or extra occurrences. Transferred Unknown anchors join later explicitly Unknown repeats; process references do not duplicate them. Warning occurrences remain distinct from JSONL/envelope, request and native-call units. These relations apply whenever aggregation IDs exist, including a legacy count-summary contract.

The two exact Unity/Error material-renderer NullReferenceException messages qualified by `MaterialNre.StandardMessage` and `MaterialNre.LodMessage` use a separate error family. Eligibility requires ordinal equality of the complete message, source Unity, severity Error and explicit null `exception_type`, `stack`, `caused_by_event_id` and `failed_listener`. A changed stack/message, another source/severity, missing/null-contradicting metadata or an unqualified exception follows the full ordinary diagnostic path. The two variants remain separate patterns. The first full `runtime_log` keeps its original message and adds `error_id`, `error_occurrences` (1), `error_first_utc`, `error_last_utc`, `error_origin`; absent error fields are omitted. Repeats are `runtime_error_repeat` with exactly the seven producer fields `error_id`, `origin`, cumulative `occurrences`, callback `utc`, `event_id`, `thread`, `phase`. Each repeat advances the ordinal by one. The archive derives first/last UTC from saved callback timestamps, including decreasing timestamps; repeat-only `delta`, `first_utc` or `last_utc` are rejected whenever present, even null or container values. Anchors/repeats require canonical decimal-string `event_id`, positive numeric `thread` and nonempty string `phase`; an anchor's event ID equals its error ID. Final `runtime_error_summary` contains `error_id`, `origin`, `occurrences`, `first_utc`, `last_utc` and adds no occurrence. Error console forwarding is unchanged; no original native error is suppressed or repaired by aggregation.

Optional readable `error_summary` reports count/time/missing-final-summary values independently recounted from error anchors/repeats, with `scope: exact_known_unity_material_nre` and `basis: saved_anchors_and_repeat_ordinals`. It counts only the two qualified material NRE patterns, not all runtime Error/Fatal events, and is separate from warnings and recorder `observer_errors`. Warning summary shape and `saved_anchors_and_repeat_deltas` basis remain unchanged. Error identity is origin plus error ID; cross-origin, orphan/duplicated references, missing ordinals, invalid final extrema, unqualified full anchors or false manifest summaries fail packaging with originals retained. The external ledger sorts category7 by occurrence signature like warning category6, including spills and out-of-order callback timestamps. Transferred Unknown originals join explicitly Unknown later repeats; a reference marker adds no occurrence. These validations apply even if an archive declares the legacy count contract; old archives with only full errors and no error aggregation fields remain supported. Arbitrary diagnostic messages/stacks are syntax-validated without retention or an8KiB body limit; bounded streaming exact matching and explicit null-kind/duplicate-field checks qualify an error anchor independent of JSON property order. Partial Error metadata and non-null mixed Warning metadata are invalid even when their ID is a container or null; the actual full anchor's all-null Warning fields remain valid. Every repeat still has a durable event record, so repeated-error metadata grows with observed occurrences; no full-run size cap or finite-mechanic coverage is implied.

Normal shutdown is separate from complete observations and native acceptance. Explicit omissions, required read failures, missing owner/identity, unmatched native/request phases, recovery and reported failures remain readable incomplete reasons. `coverage.state=not_certified` means saved observations alone do not certify all gameplay. Producer statuses are retained as finite control metadata with a 1 MiB packaging bound; oversized controls fail honestly with originals retained, without clipping gameplay payloads. Original API/native values and large/deep payloads are syntax-checked through streaming projections without legacy body/node/depth/list truncation.

The Unity source subscribes once to `logMessageReceivedThreaded`, which delivers both main-thread and background-thread events, preserving complete supplied exception stacks. It retains its native/managed callback lifetime and removes only its own subscription on disposal. It does not also subscribe to the ordinary event or overwrite other subscribers. Diagnostic stop still seals admission and drains accepted events; messages emitted after the declared stop frontier are outside capture. Callback coverage is not evidence that a particular earlier untimed exception occurred before that frontier or that its underlying game fault is repaired.

Original decoder returns use the distinct raw stage `native_decoder_result`; earlier `client_decoder_result` records remain accepted as a separate compatibility stage. Both retain exact bytes and request ownership without adding API request/response units. Derived recorder parsing is labeled separately and cannot create another original API send or client application. `native_parse_input` retains the full original MergeFrom byte argument and integrity fields as a diagnostic envelope, including unknown fields; it adds neither raw-body stage records nor API request/response records. Its readable message view names its known-field scope. A native fault records `native_original_threw` without inventing an exception type. A failed phase snapshot is unavailable, not an entry snapshot relabeled as the later phase.

The descriptor's logical route/native operation identifier, physical HTTP URI/path and raw request-header identifier are separate observed values. Only an exact native owner edge binds a descriptor to a request. An early binding establishes stable saved ownership; a late binding supplements logical metadata without rewriting already committed route/system/operation owners. Path or identifier resemblance does not establish a join.

## Verification and trust boundary

A completed archive is re-read to EOF: exact five names, manifest/stream CRC, extracted SHA-256/byte/record counts, strict JSON/UTF-8, raw-body bytes/hash and request ownership, record identity uniqueness, session scope and readable-summary equality must agree. Fresh streams match the source facts verified during their build; existing and recovered archives also compare exact retained committed source bytes, allowing only the declared recovery marker beyond the diagnostics prefix. Current context/status cannot claim completeness merely because archive hashes match.

These checks establish consistency with supplied records and saved prefixes. `authenticity` remains `unverified`: a modified producer can fabricate a consistent trace, identity and manifest. No count/checksum proves official gameplay or recorder execution. Manual submission review/points remain the user's decision. Website intake and native/hardware acceptance are separate owners and are not certified by managed archive checks.
